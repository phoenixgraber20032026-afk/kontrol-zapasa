# Перенос программы на GitHub: сайт + настольная версия (.exe)

Что получится: один репозиторий `kontrol-zapasa`, из которого автоматически публикуются **сайт** (GitHub Pages)
и **установщик Windows** (Releases). Данные по-прежнему живут в вашей Google-таблице; сайт и программа
только отправляют запросы в Apps Script. Все пользователи работают одновременно, как и сейчас.

## Шаг 0. Обновить Apps Script до v1.7 (обязательно — без этого сайт не подключится)
1. Редактор скрипта таблицы → файл `KZ_Web` → заменить содержимым `gas/KZ_Web.gs`; файл `KZ_WebApp` → `gas/KZ_WebApp.html`.
2. Развернуть → Управление развёртываниями → ✎ → Версия «Новая версия» → Развернуть. Доступ должен быть **«Все»**
   (ANYONE_ANONYMOUS), выполнять «от моего имени».
3. Скопируйте URL веб-приложения (заканчивается на `/exec`). Проверка: откройте в браузере `<URL>?ping=1` —
   должно показаться `{"ok":true,"app":"kz","ver":"1.7",…}`.

## Шаг 1. Репозиторий на GitHub
1. github.com → New repository → имя `kontrol-zapasa`, **Public** (GitHub Pages в бесплатном тарифе работает
   только для публичных репозиториев; в коде нет секретов: пароль WIZARD хранится в Apps Script, адрес `/exec`
   пользователь вводит сам). Без README (у нас свой).
2. Положите в него содержимое этой папки. Проще всего — **GitHub Desktop** (File → Clone → выбрать репозиторий →
   скопировать файлы в папку → Commit → Push). Или на странице репозитория «Add file → Upload files»
   (перетащить все папки целиком).
3. Если логин GitHub не `phoenixgraber20032026-afk` — замените его в `desktop/package.json`
   (`repository`, `build.publish`) и в `desktop/main.js` (`SITE_URL`).

## Шаг 2. Сайт (GitHub Pages)
1. Репозиторий → Settings → Pages → **Source: GitHub Actions**.
2. Actions → «Сайт (GitHub Pages)» → Run workflow (дальше он запускается сам при каждом push в `main`).
3. Через 1–2 минуты сайт доступен по адресу `https://<логин>.github.io/kontrol-zapasa/`.
4. Откройте сайт → экран входа → **«⚙ Адрес программы Google»** → вставьте URL `/exec` → «Проверить и сохранить».
   Адрес запоминается в браузере. Чтобы сотрудникам не вводить его, дайте ссылку с параметром:
   `https://<логин>.github.io/kontrol-zapasa/?api=https://script.google.com/macros/s/…/exec`
   (после первого открытия адрес сохранится, параметр из строки исчезнет).
5. Установить как приложение: в Chrome/Edge — значок «Установить» в адресной строке (или меню → «Установить
   приложение»); на телефоне — «Добавить на главный экран». Страница кэшируется (открывается мгновенно),
   данные — из Google при наличии связи.

## Шаг 3. Настольная версия — установщик .exe
Собирается **на серверах GitHub**, на вашем компьютере ничего ставить не нужно.
1. В репозитории создайте метку версии: GitHub Desktop → History → правый клик по последнему коммиту →
   Create Tag → `v1.7.0` → Push (или `git tag v1.7.0 && git push --tags`). Номер метки = `v` + `KZW.VERSION` из
   `gas/KZ_Web.gs` + `.0` (1.7 → v1.7.0, 1.8 → v1.8.0); иначе сборка предупредит о несовпадении версии. Либо Actions → «Настольная версия
   (Windows .exe)» → Run workflow.
2. Через 5–8 минут в **Releases** появится `KontrolZapasa-Setup-1.7.0.exe` (≈90 МБ, внутри Chromium).
3. Установка: запустить, выбрать папку, готово — ярлык «Контроль запаса» на рабочем столе. При первом запуске
   укажите адрес программы Google (как на сайте, шаг 2.4). Windows SmartScreen предупредит о неизвестном
   издателе (подпись кода не куплена): «Подробнее» → «Выполнить в любом случае». Подпись сертификатом
   можно добавить позже (секреты `CSC_LINK` / `CSC_KEY_PASSWORD` в Actions).
4. Обновления: при следующем выпуске (новая метка `v1.7.1`) установленная программа сама скачает новую
   версию и предложит перезапуск (Справка → «Проверить обновления» — вручную).
5. Собрать на своём ПК (если нужно без GitHub): установить Node.js с nodejs.org → запустить
   `desktop/СБОРКА_на_своём_ПК.cmd` → установщик появится в `desktop/dist/`.

## Шаг 4 (по желанию). clasp — код скрипта в репозитории
Чтобы не копировать файлы в редактор вручную:
1. Установить Node.js, затем `npm install -g @google/clasp`, `clasp login` (войти в Google-аккаунт владельца таблицы;
   на script.google.com/home/usersettings включить «Google Apps Script API»).
2. ID скрипта: редактор → Настройки проекта → «Идентификатор скрипта». Скопировать `.clasp.json.example` →
   `.clasp.json` и вставить ID.
3. Первый раз: `clasp pull` — в папку `gas/` придут все файлы проекта (Code.gs с KontrolZapasa v2.0 и др.).
   Закоммитить. Дальше правки — в `gas/`, отправка в Google: `clasp push`, затем новая версия развёртывания
   (`clasp deploy -i <ID развёртывания> -d "v1.7.1"` — чтобы ссылка `/exec` не менялась).
4. `node tools/build.mjs` копирует `gas/KZ_WebApp.html` в `app/index.html` и подставляет номер версии
   в `sw.js` и `desktop/package.json` (Actions делают это сами при публикации).

## Как это устроено (для понимания)
- `KZ_WebApp.html` определяет режим сам: если есть `google.script.run` — работает как раньше; иначе режим «сайт»:
  каждый вызов — `fetch POST` на `/exec` с телом `{"api":"kzwXxx","args":[…]}` (Content-Type text/plain, поэтому
  браузер не делает preflight, а Apps Script отвечает JSON с разрешением CORS). `doPost` → `kzwApi_` пропускает
  только публичные функции `kzw[A-Z]…`; права внутри них проверяются по токену (`kzwAuth_`), как и прежде.
- `doGet?ping=1` — проверка адреса (кнопка «Проверить и сохранить»).
- Настольная программа — Electron: окно с той же страницей из `app/`, адрес Google хранится в профиле программы,
  меню «Программа → Адрес программы Google…» сбрасывает его. Звук предупреждения в настольной версии играет без клика.
- Сайт/программа без интернета открывают интерфейс (кэш), но данные получить не могут — покажется
  «Нет связи с Google». Полноценная работа без связи и ускорение — следующий этап (Cloudflare Worker + D1,
  как в «Планирование сервис» v3.29).
